# 通用工作模型能力增强计划

状态：整体架构计划；通用协作核心第一版已落地，见第 10 节。完整收益评估与后续策略校准待用户实际任务反馈。用户已接受以真实提升为依据的架构级改动与重构，尚未发布新版本。

## 1. 目标与定位

目标是提高工作模型在不同任务中的实际表现：理解准确、依据充分、选择合理、行动有效、能够自我纠错、交付诚实。编码、写作、资料研究、数据分析、设计与长任务协作使用同一套核心机制，任务内容不同，生成的辅助和验证方式随之变化。

插件提供持续的协作支持：维护有来源的任务状态与证据，编译当前真正有用的上下文，帮助工作模型选择下一步，并在关键处引入独立顾问。工作模型继续负责领域判断与实际工作；用户继续决定目标、偏好和授权。增强来源是更好的信息和决策循环，效果以任务结果验证，不以提示词长度、顾问次数或模块整洁度认定。

本计划承接[任务意图稳定性计划](0.7.8plan.md)、[单轮顾问计划](0.7.9plan.md)、[顾问协作契约](ADVISOR-CLOSED-LOOP.md)、[阶段协作重构记录](PLAN-ADVISOR-COLLABORATION.md)。既有编号、版本绑定、来源约束和取消机制优先复用；旧文件保留为历史与已实现边界记录。本提案讨论未来架构，不将提案冒充已生效事实。

## 2. 不能破坏的边界

1. 原话保留。解释、辅助包、顾问和学习模块都不能伪造用户要求、授权或接受失败。
2. 每条真实用户输入都要被理解。兼容默认保留逐轮解释；“已理解、无新增条目”成为正常状态。是否产生辅助增量，与是否完成理解分开。
3. 当前轮辅助条目重新生成并绑定当前输入；上一轮机器推导不得自动继承。任务原始消息、用户明确的决定和约束可以作为有出处的背景保存，是否适用于当前动作须重新判断，撤回或切换后立即失效。
4. 工作模型保持自主性：可逆实现选择由它决定，只有会改变用户目标或授权且无法自行查明的分歧才询问用户。查证、阅读和普通修复无需增加确认步骤。
5. 保留[ADR-0085](DECISIONS.md)的原则：插件不增加解释模型的单次输出 token 上限。控制重复、选择相关上下文和咨询机会；不靠截断发挥来省钱。
6. 工具、文件、网络与图像能力沿用宿主授权和实际可用性；增强能力不构成新权限。不为获取证据擅自启动重型实验或对外操作。
7. 小事能直接完成，复杂任务可以深入；阶段数、咨询数、候选数、输出长度不作为质量配额。
8. 调用成功、检查通过、局部成果通过、整个任务完成保持分离。顾问没有替用户接受偏差的权力。
9. 相同输入和配置不能跨会话串包，异步迟到的解释与顾问报告不能覆盖更新后的任务状态。

## 3. 为什么需要重组

现有链路已提供解释、辅助包、只读查证、顾问和阶段记录，但它们对任务、轮次、材料和结果的理解还不完全一致。以下源码观察用于确定设计缺口；它们不证明新架构已有收益。

| 当前观察 | 通用影响 | 新架构承接 |
|---|---|---|
| 实际覆盖提示词与内置提示词都要求至少一条；空条目进入重试和兜底 | 清楚请求、承接或确认也可能被补成无增量内容 | 独立的意图识别结果与可为空的辅助增量 |
| 引文校验检查子串存在，未验证正文所有实质动作由引文支持；对抗构造可保留扩写要求 | 不同任务都可能出现范围、否定或授权扩张 | 原始引文留存、条目拆分、来源与语义充分性检查 |
| 相同历史被同时放入解释器 system 和 user；固定顾问协议为 1164 字符，在意图包预算外拼接 | 重复、重点稀释，名义预算与最终额外输入不一致 | 单一上下文编译器，统计最终投影并消除重复 |
| 辅助包按会话字符串取回；本机覆盖文件优先于包内提示词 | 旧轮包与旧提示词可能被当成新状态 | 输入事务绑定、提示词版本与差异显式记录 |
| 非阶段顾问只取最近真人消息；“继续”快照只剩“继续” | 顾问可能丢掉原任务和已批准范围 | 共用任务来源与本轮增量，取相关证据而非单条消息 |
| 顾问快照不直接吸收 PTC 子调用；依赖外层输出或显式材料 | 未打印的内层原始结果可能不进入复核材料 | native/PTC 统一证据事件 |
| satisfied 要求结果证据，failed 允许空引用 | 无依据的否定也可能影响后续动作 | 满足、失败、未验证均有清楚证据语义 |
| 阶段门能拒绝其自身 advance，模型是否调用仍依赖主动行为 | 工具存在不能证明关键检查被执行 | 可观测的介入机会和工作模型协作提示 |
| 实验文档区分工程通过与效果通过，效果/成本仍有缺口 | 不能用大量测试宣称能力明显提升 | 真实任务对照、消融、盲评及运行配置指纹 |

上述观察来自[解释器](../po06/lib/interpreter.js)、[输入流水线](../po06/lib/pipeline.js)、[宿主接线](../po06/lib/index.js)、[顾问](../po06/lib/advisor.js)、[效果验收记录](../po06/RELEASE-CHECKLIST.md)。此前 HOME、profile、卡片、主题、打包门等修复作为运行可靠性基线保留；“issue 关闭”或源码链接正确不代替运行实例实际加载的证明。

## 4. 目标架构

默认在现有插件包内重组，保持对外工具和宿主契约可兼容。核心划成六个职责，可独立关闭、比较与替换：

| 职责 | 做什么 | 预期可观察改善 | 不做的代价与风险 |
|---|---|---|---|
| 任务与证据状态 | 保存原始输入、已明确决定、当前动作、事实、假设、工具结果和成果版本 | 追问不忘原任务，任务切换不继承旧约束，结论可回查依据 | 多套状态各自推断；错误压缩可能把推断变成事实 |
| 意图与不确定性分析 | 理解本轮动作，识别影响结果的未知与真实增量 | 少误解、少追加目标、少把可查事实问给用户 | 语言被复述但关键歧义遗漏；过度推断也可能扩大任务 |
| 上下文编译 | 从有来源状态选择、压缩、组织当前所需信息 | 更少重复，重要约束保留，模型容易知道下一步的依据 | 一切材料堆进上下文；错误筛选会丢关键约束 |
| 工作过程协调 | 比较下一步行动的证据价值、后果、可逆性和必要验证 | 少重复试错，及时查证，能把复杂问题缩成区分实验 | 模型沿旧假设走到底；过度协调会增加开销 |
| 独立顾问 | 针对当前判断、策略、成果或交付覆盖挑战证据 | 更早发现错误假设与缺陷，已有通过只重查受影响部分 | 只在最后形式验收；顾问自身误判或过度否定 |
| 结果评估与策略校准 | 记录实际结果与代价，比较辅助策略的真实效果 | 保留有效增强，剔除无收益机制，针对模型差异调整 | 只累积规则，缺少是否有用的证据；自我评价可产生偏差 |

流程示意：

~~~mermaid
flowchart LR
    U[用户原话与明确决定] --> T[任务与证据状态]
    E[工具结果与成果版本] --> T
    T --> C[选择当前需要的辅助]
    C --> I[编译相关上下文]
    I --> W[工作模型判断与行动]
    W --> E
    C --> A[必要时独立顾问]
    A --> T
    E --> V[真实结果与策略评估]
    V --> C
~~~

### 4.1 共用状态，保留来源和时间

状态是一份带来源的工作视图，不是一段不断加长的总结。最小信息包含：

- 原始任务来源、当前人类输入、明确的目标与决定、待完成结果。
- 每项内容的身份：用户明说 / 实读事实 / 模型假设 / 实现建议 / 未验证。
- 事实或证据的来源、读取范围、版本、获取时间和失效条件。
- 当前行动、观测结果、未解的问题、下一步待区分的假设。
- 复核目标、有效检查点、未闭合项及其对应成果版本。

任务边界由明确任务切换或能核对的输入关系确定；不因普通追问重开任务，也不因复核报告存在就强留旧任务。多任务分支保留来源关系并分别投影。对于“不遗传目标”，保存的是可追溯的原话背景；每轮机器推导仍独立生成，未经用户采纳的建议不转为长期要求。

同一个证据可以在理解、行动和复核间复用；附带范围与版本。native 和 PTC 子调用走相同的采集口，记录真实参数、输出、退出/错误与调用关系，去重外层聚合结果。不执行或不读取的材料不能升级为已验证。来自第三方内容的指令不会因进入状态而取得用户身份。

### 4.2 意图理解与辅助增量分开

把“这一轮是什么动作、目标是否变化、有哪些真正影响决策的未知”作为理解结果；需要新增的解释、事实、选择与检查另列。零增量合法，正常显示“已理解，无需新增辅助”。理解失败则显示明确失败，不用模糊 unknown 冒充有效产出。

用户明确要求保留逐字依据和原始引文；正文包含多个实质动作时分别核对出处。字符串校验维持机械边界，语义支持关系不得假装由字符串证明。明显越权或无法支持的条目不进入明确要求；不确定的推导保留身份、影响和可验证方法。只在有实质分歧时使用语义复核，不把每句话送到另一模型。

知识与能力补充来自当前任务的实际资料、可用工具、已有技能及工作模型/顾问的领域知识。核心不内置按行业写死的检查清单；检索或领域模块即便加入，也须按目标、依据与效果选择，能关闭和单独消融。

### 4.3 注入按信息价值编译

保持一份稳定、简洁的协作边界；动态部分只表达本轮新增或发生变化的相关状态。正文优先保留：当前目标变化、必要约束、决定行动的事实、会改变结果的未知、具体未解问题。必要时补充候选行动和验证方式；无需填满全部章节。

同一历史不在 system 和 user 重复。聚合注入复用宿主 snapshot 的替换/去重语义，同时插件自己验证 session/input/task/revision。新输入到来时撤销不属于它的辅助包，异步旧结果不重新激活。总量统计包括顾问协议、状态、反馈和意图包，区分总输入、可缓存稳定输入与新增输入；不拿一个局部预算冒充全部开销。

复杂任务的内容压缩依据相关性与决定价值，不能靠任意砍掉末尾或给隐含约束排低优先级。所有丢弃范围透明，关键事实缺失时保留未验证。提示词拆成版本化的身份/来源契约、可编辑的表达策略和运行时相关材料；升级明确显示生效来源与自定义差异，不覆盖用户自定义文件。

### 4.4 协调器选择当前最有价值的干预

协调器评估的是问题结构：不确定性、错误后果、可逆性、证据充分性、是否有新信息、当前进展与验证成本。它提出或选择干预，工作模型继续决定具体实现和行动。

干预有从轻到深的连续范围：不加辅助、简短消歧、提示一个需要核对的事实、辅助比较方案、提出区分实验、请求独立顾问、汇总交付覆盖。深度可升可降；无需每任务按同样阶段走一遍。不使用“短消息就是简单”“有某关键词就必须顾问”“做满几次咨询才算完成”等判据。

对于结构性选择，先考虑能否用小实验减少不确定性；保留合理替代路线，但不把候选数当配额。对于已清楚且可逆的任务，直接执行。对于重复失败，先问下一次尝试会改变哪个假设、带来什么新证据；没有信息增量则缩小实验或改变方法。用户纠错之后更新假设与证据，不只加一句“以后注意”。

观察能力和决策能力分开验证。工具/环境是否可用由当前事实与失败原因判断，不能由一次失败推出永久无权限；过期能力事实撤销。协调器自身判断也可以错误，所以保留理由、结果与用户纠正，避免用它的自评分证明它正确。

### 4.4.1 主动提升能力的通用动作

增强同时包括提高好结果的上限：帮助工作模型形成更好的构思、使用领域知识、拆解复杂目标、推演方案后果，并组织适合用户的表达与交付。以下动作是可组合的能力，不是每轮必填章节：

| 通用动作 | 随当前目标生成的内容 | 验证真正有收益的现象 |
|---|---|---|
| 目标具体化 | 从用户的结果方向提炼可观察的成功现象，区分要求与解释 | 首轮结果更贴合用户，且未新增产品范围 |
| 补足知识与方法 | 检索与当前决定相关的资料、工具/技能用法、已有方案；说明适用边界 | 工作模型使用正确资料做出原来做不到或做不好的结果 |
| 构思与方案探索 | 在开放任务中产生有差异的思路，推演取舍；不以候选数量代替质量 | 可用方案或创意质量提高，用户盲评更倾向候选结果 |
| 分解与组合 | 识别依赖、可独立验证的子目标、可并行工作与整合风险 | 复杂任务少漏项，能形成完整结果，而非局部看似完成 |
| 假设与实验 | 区分已知、推断、替代解释，设计最小有效实验 | 少沿错误假设重复试错，下一步实际减少关键不确定性 |
| 表达与交付适配 | 根据受众、用途、载体和证据组织结果，标明可用部分与局限 | 内容更易理解和使用，用户无需反复要求换一种形式 |

领域内容由原话、相关资料、技能和模型能力产生；这些动作的选择依据当前缺口与机会。缺信息时补事实或提出合适问题；开放空间时鼓励有差异的构思；任务已经明确时专注完成，不套“更复杂才更专业”的流程。

初版协调策略复用已有解释/顾问模型配置，输出“当前需要的动作、依据、预期信息增量、影响范围”或“无需介入的理由”。事件归一、版本、去重和权限用确定性代码处理；语义决策由模型提出并记录。重要上下文先按来源和关系保留，再在候选材料中排序，不把任意字数或关键词评分当通用价值函数。实际结果持续用于校准介入阈值；角色可共享同一模型但使用独立上下文，不静默切换更昂贵模型。

### 4.5 顾问从末尾验收扩展到关键判断

复用已有任务/阶段/check ID、证据哈希、取消、局部失效机制。顾问支持三类目的：挑战关键假设或方案、检查重复试错是否有信息价值、核验成果及交付覆盖。继续兼容现有 diagnose_failure 与 review_result；新增目的须有明确输入输出，不通过修改旧参数让老客户端悄悄变义。

介入依据当前需要，不依据固定次数或任务行业：高后果且依据薄弱的判断、用户指出偏差、同路失败无增量、准备依赖未检查成果、准备声明与证据不一致，都可能需要独立顾问。普通讨论可以简短直接，带争议或反复改口的解释也可能需要诊断。

顾问使用原始任务来源、本轮补充、相关原始证据、检查目标和当前版本。避免只把“继续”当完整任务，避免先读执行者的通过结论。顾问可以指出检查目标遗漏，但新增偏好或产品范围不得升级为用户要求。

明确区分：满足=有相关证据支持；失败=有可定位的偏差证据；未验证=材料或能力不足。顾问误报也要被针对性反证纠正，不采用模型多数票。格式错误可以有限重整同一报告；语义与证据错误不能靠反复重生成直到 pass。

首轮材料准备校验、证据编号和版本绑定自动完成，减少模型手填协议字段。只复核受影响目标，避免改一个局部重审整个项目。相同版本的有效结论可以复用；依赖不明则如实限制结论。

协调器先以可观测建议工作；是否自动发起有成本的旁路顾问由用户现有辅助/自动配置和可取消策略控制。默认不为了每个工具调用再调用一个模型。检查机会、实际采纳、跳过理由与有效纠正率都可观测。

硬拒绝限于确实可验证的契约和插件自己的接口，沿用用户授权。当前宿主不能被假定具有最终文本 veto；一段状态文本不构成强制交付门。若更强自动拦截需要宿主新契约，必须先验证并另设可逆入口，不能绕过原权限或破坏会话。

### 4.6 反馈与策略校准

工作结果、用户纠正、实际验证和顾问发现是反馈来源。通过自评、被点击“继续”、没有新消息，都不自动等于任务成功。失败分成目标理解、资料依据、策略选择、工具/环境、成果实现、验证遗漏等原因，但分类可多选/未知，不强迫归一。

短期先做有来源的本任务经验与离线策略建议；需要持续更新默认策略时，经过冻结评估、留出验证和可回滚版本。用户在一个案例里的偏好不扩成全局约束。不会自动改提示词、训练模型或向外上传会话；逐轮新增“禁令”不能作为自我优化方式。

## 5. 如何证明通用而灵活

同一核心根据用户目标和证据形态工作，无需为下面每类增加业务分支。以下仅为开发验证场景，不是注入给所有任务的固定清单。

| 场景 | 当前真正缺什么 | 同一机制应怎样变化 |
|---|---|---|
| 明确的小改动或短答 | 信息可能已经齐全 | 理解后零/少增量，完成最小必要检查，无流程填充 |
| 改已有程序 | 接口约束、实现与运行结果 | 从原话保留边界，读取相关依赖，按实际错误复核 |
| 查证一个有争议的结论 | 来源可靠性、相反证据、适用范围 | 聚合有来源资料，给出区分假设的最小调查，不套程序测试流程 |
| 修改文章或报告 | 受众、意思、事实与表达偏好 | 分开事实与风格，保留作者意图，只核对相关引用/结构 |
| 数据分析 | 口径、数据缺失、假设与可复现步骤 | 保存数据来源与计算证据，区分推断和结果，不凭语言自信结案 |
| 视觉/交互成果 | 实际画面、交互证据与审美取舍 | 基于真实附件/产物检查可观察事实；主观观感与手感由用户体验，能力不足如实未验证 |
| 长任务、纠正与任务切换 | 原任务、已决定项、当前变化、过期证据 | 重建本轮工作视图，承接明确授权，撤销旧推断，只复核相关变化 |

## 6. 实施与验证路线

这里的阶段是开发顺序，运行时不会强制用户任务照此执行。可以并行独立工作，但关键数据契约先验证；每段结果形成后先自验原始证据，再定向顾问复核。阶段通过只覆盖该阶段。

| 阶段 | 交付与主要改动 | 验证与进入下一段条件 |
|---|---|---|
| P0 基线与观测 | 冻结当前可回退产物、实际加载指纹、配置、提示词来源、模型与调用参数；建立结果/成本记录 | 两端能指出实际用哪份代码与提示词；一条输入及其解释/行动/顾问可追溯；不运行未经估算的大评测 |
| P1 共用数据与证据 | 在同包内建立任务视图、来源/事务/证据契约；native/PTC 事件统一；老工具接口映射至新内部结构 | 覆盖追问、撤回、并发、迟到报告、跨会话、重启、外部写入与错误结果；不得把未验证自动变成通过 |
| P2 意图与上下文编译 | 分离理解与增量；引文留存、扩写检查、相关性选材、去重、版本化提示词与消息绑定 | 清楚请求少冗余；复杂请求不丢关键约束；多轮纠正不遗传已失效项；先影子生成再与当前投影比较 |
| P3 自适应工作协作 | 接入干预选择、候选方法/小实验、可观测机会与选择理由；工作模型保留自主实施 | 不同任务的辅助不同且无需改代码；简单任务无强加阶段；连续失败时下一步真正区分假设；做小规模真实对照 |
| P4 顾问与结果闭环 | 共用任务/证据、关键判断咨询、证据型正反判定、局部复核、覆盖和有限格式修复；明确失败分类 | 关键机会不因未调用工具而不可见；顾问有效发现与误报有计数；PTC 证据可直接核对；无无限重试和新授权 |
| P5 价值验证与迁移 | 跨领域跨模型对照/消融、兼容回归、配置与状态迁移；有收益机制逐步启用 | 满足预注册效果与退化边界，代价可控；双端实际加载与回滚通过。发布、合并与大范围默认切换作为独立操作 |

新内部契约可以重构 interpreter/pipeline、上下文生成、advisor/stage/coverage 的重叠部分，把大入口中的职责拆开；现有成熟运行时、取消、路径校验、编号与哈希机制保留或经等价验证迁移。清晰结构的价值要体现为可追溯、少失效与可替换，不为模块数量而拆分。

## 7. 收益评估与“大的提升”门槛

比较三组：原话直达且插件关闭；冻结现有插件；候选新架构。先用小开发集检查方向，再用独立留出任务检查泛化。不同模型分别比较同模型条件下三组，不把换更强模型的收益记到插件。初始覆盖至少两种不同模型和三种性质不同的任务；样本不足时仅报告方向，不作整体提升结论。

记录首次可用率、关键目标遗漏、无依据需求扩张、严重错误/误判、返工和多余追问；开放任务另评可用构思、领域资料利用、表达与交付质量，避免只统计“少犯错”而漏掉能力上限的提升；同时记录总耗时、每轮新增/可缓存输入、token 与工具代价。顾问记录有效发现、无依据否定、漏掉的必要机会、材料准备失败、局部重复复核和后续修复是否闭合。

真实标准随任务确定并冻结：程序用实际测试/行为，事实分析用来源与计算，写作以意图保持和读者效果判断，主观视觉/手感由用户体验。顾问和执行者的评分不是唯一结果标签。实验样例隐藏缺陷的发现可机械核对；主观结果用随机顺序比较，减少知道分组造成的偏差。

效应门槛在 P0 基线采样之后、候选调参之前写入评测协议：定义何种首次可用率提升或严重错误下降值得其代价，以及允许的延迟/费用/退化范围。尚未采样，不填伪精确成本或承诺倍数。大提升需跨任务/跨模型反复出现并超过自然波动；单题或小样本的大数字不足以默认启用。

对关键模块做消融：去掉新的任务视图、上下文编译、干预选择或顾问策略，观察收益是否消失。对提升无贡献、只增加等待或追问的机制收窄/移除；某模型或某场景才有效的机制仅在对应条件启用，核心无需写死行业。未满足效果门的新结构保持实验状态，即便工程测试全绿。

不把本轮源码复现或顾问计划通过视为新架构效果证据。真实模型实验先记录规模与预计花费，使用明确的实验任务或经用户授权的会话材料，未采集的数据标缺失。

## 8. 双端、兼容与迁移

同一包的 host 核心服务浏览器 web 与桌面端；客户端只展示状态和控制，保证业务语义一致。宿主适配层明确区分 0.1.7/0.2 的可用 API、native/PTC 展示与 SDK 调用，使用能力检测和契约测试，不按外壳猜工具名称或可见性。

保持现有工具名和基本参数可用。新操作若需改变语义，使用显式协议版本或新接口，旧调用经兼容映射并给出可核对的结果范围。业务结果与可选展示字段分开：关键结果不合法时返回明确无效报告并撤销通过，不能用无声 null 替代整个报告；可选字段在传输边界做受控 JSON 归一，保留诊断。

提示词覆盖文件显示来源、版本和差异；不静默覆盖用户自定义。旧阶段与证据可读、可归档，缺少原始来源的新状态标 legacy-unverified，不直接赋予完成资格。先在隔离数据目录演练迁移，再启用，备份和旧渲染路径能恢复。

浏览器和桌面两个独立宿主共享 home 时，新增状态不能假设永久单写者：采用实例隔离/明确所有者/原子更新，或在未实现多写者协调前明确拒绝同任务双写。需要验证非作者机器、不同目录、换预设、热开关、取消、断线与重启。

host 改动与 client 改动分别记录已加载指纹；源文件新不代表实例新。使用支持的重载路径，热更新不可证明时明确需要重启，不通过改写无关 patch 冒充生效。不自动重启正在承载本会话的宿主，不擅自推送/合并或发布。

## 9. 本轮产物与后续起点

本轮仅形成这份计划以及定向复核记录。未改程序、配置、提示词覆盖或默认顾问策略；没有开展新跑分。下一次实施从 P0/P1 起点开始：先统一可追溯数据与证据，再以 P2/P3 的小规模真实对照验证方向，随后扩展顾问与策略校准。架构级重构可用，但是否成为默认以 P5 的真实效果决定。
## 10. 第一版实现记录

- 新增通用 capability 核心，生产输入与 native/PTC 事件接入；任务原始来源、当前理解、辅助建议、重复失败与顾问待核对项分别保存，按当前输入投影。
- 理解完成允许零新增条目；原始引文保留，转述单列，摘录不当成完整授权清单；默认不再附加按任务关键词挑选的行业 playbook。
- 同一历史不再同时进入解释器 system 与 user；协作建议由当前任务生成。并行会话编译参数、输入 epoch 与取消信号分别绑定。
- 顾问复核可承接原任务与后续补充，PTC 子调用作为结果证据，空引用 failed 保持未验证。上下文反馈使用实际事件缓存的目录，并筛掉不属于当前任务的旧阶段反馈。
- 当前桌面宿主已通过受支持热重载加载 protocolVersion=1、mode=adaptive，真实状态接口 HTTP 200 可核对输入来源与 PTC 计数；客户端刷新取更新显示，web 端共用同一源码。
- 仅跑 7 项定向行为检查与既有顾问注册兼容检查，均通过；未跑全量、变异、发版门或新模型评测。源码复核的四个检查项有证据支持，整体报告仍标未验证（长会话截取及未开始新的真实一轮）；不宣称效果提升已验收。
- 用户可直接试：简短确认、两类不同任务的辅助内容、承接“继续”后的顾问复核。后续自动策略校准和大范围收益验证未声称完成。

## 11. 解题贡献补齐（协议 v2，待真实任务验证）

此前第一版以理解、状态与纠错可靠性为主，还不能据此声称工作模型明显更强。继续实现中增加直接能力内容：

- 辅助模型先独立推演任务的关键规律、方法与取舍，再把具体内容写进 support.contribution；不是只告诉工作模型去比较或思考。内容不固定领域、章节或方案数量，简单输入可以零增量。待核对前提保留为 assumptions，项目事实仍须有实际资料。
- contribution 与 assumptions 完整通过解析、状态与动态投影，工作模型结合原话和证据采纳、修改或反驳。用户自定义提示词不覆盖，输出契约在组装时附加。
- 顾问增加 develop_approach：在关键难题、开放任务和方法选择时独立贡献实际解法，不必先出故障。旧 diagnose_failure/review_result 继续使用；新建议不记入验收覆盖、不授予通过或完成、也不清掉已有复核问题。
- 卡片区分独立解题、失败诊断与验收，展示解题贡献及前提。当前宿主已加载协议 v2；客户端刷新取新版。
- 小范围行为验证确认内容传输和建议身份，含成功/失败的注册执行路径；没有开展模型效果对照，也没有声称知识、推理或创意已经大幅提升。真实价值应看产出的解法和最终成果是否更好，额外建议也可能无益或误导，需要用户实际任务反馈。
