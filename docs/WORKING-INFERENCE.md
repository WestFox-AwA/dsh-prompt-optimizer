# 工作模型推理增强（实际测试版）

在会话输入区打开“优化选项”，开启“推理增强”。该开关默认关闭，按会话保存，与提示词辅助档位独立；也可在插件设置页配置默认值。工作模型由宿主会话决定，增强沿用同一 provider/model 与已有输出上限。新增“增强强度”独立控制候选和择优/反馈的思考档位，不修改会话的工作档位。默认“快速”：Flash 的候选/修订用 low，择优/反馈用 off；“均衡”用 high/low；“跟随工作档位”保留原强度。只使用模型目录明确支持的档位，目录不可用时保留原档位并在过程记录中说明。降低思考强度可能影响解题质量，可用另外两档作对照。

- 多候选择优：每次工作生成产生2或3份完整候选，由模型对照原任务和已有事实选择一份；回复与工具动作相同时直接采用首份完整候选，跳过重复择优。
- 循环改进：先生成一份候选，再取得具体反馈；有实际修改建议时生成修订，并比较原稿和修订。反馈认为无需修改、修订没有产生新回复/动作，或比较后仍保留原稿时提前停止，不重复循环同一方案。
- 多候选 + 循环：择优时同时给出提交前必要修正的反馈，再按配置进行最多1至3轮改进，避免紧接着重做一次反馈判断。

默认建议先使用“多候选择优、2份”，便于和关闭状态作实际对照。每份候选都只是下一条回复/工具调用，生成阶段不会执行项目工具。最终只把选中的完整流交还宿主，继续由宿主管理工具执行、PTC、审批与下一步。原始请求不改写；候选、裁判和反馈调用不递归触发增强。择优是模型判断，本版没有任意项目通用验证器，也不声称效果已验证。

输入区“推理过程”可查看当前与历史生成。面板显示每一次候选、选择、反馈、修订和普通生成回退的状态、实际模型/思考档位、耗时、用量、输出、工具提议、选择理由与总结；被跳过的重复判断与提前停止也会写明原因。点击调用可切换“输出 / 返回的思考 / 工具提议 / 调用输入”。思考只展示服务商实际返回内容，缺少时明确提示，不能查看未返回的模型内部状态。默认跟随最新生成，可选择历史记录回看。

“导出这一轮完整记录”包含所有调用输入、输出、实际返回思考与决策；完整内容不以UI摘要截断。记录保存在插件 home 下 po06-inference 的profile隔离目录，最近200轮保留在索引中，可在状态接口核对位置。导出中包含当轮任务与工具上下文。

“停止额外思考”会取消当前额外调用并保留已有完整候选；没有完整候选时回退为普通生成，过程写明原因。关闭开关后后续工作生成恢复普通路径。宿主正常停止/取消会中止全部关联生成，不再提交候选。选择格式错误、服务错误或未完成反馈不会被伪装为通过；原始完整候选仍可保留。

成本随调用增加：默认parallel每次工作生成最多3次模型调用；hybrid在候选不同、无需修订时通常3次；需要一次修订并复选时通常5次；候选相同、选择失败或缺少融合反馈时实际次数会不同，面板按真实调用显示。循环模式默认最多4次。循环轮数调大时会更多，每次真实用量都可见。这是一次完整生成/代理决策的调度，不是服务器内部每个念头的复制。

当前桌面实例已验证Flash/max真实PTC路径：2次工作生成产生8次可见调用，包含2个裁判与2个反馈；仅执行1次实验工具，最终DONE。这个检查证明接线与可见性，不证明你的真实任务效果。界面的实际可用性与收益由你直接测试。
