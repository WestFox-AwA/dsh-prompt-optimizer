# 顾问流式刷新 · 改动与验证记录（2026-10-03）

## 1 现象与定位

- 现象：顾问卡片的思维与结论「看上去一秒一次刷新」。
- 定位：`po06/lib/client.js` 的 `useAdvisorRun` 用链式 `setTimeout(tick, 800)` 全量取数（每秒约 1.25 次）。
- 服务端**不是**瓶颈：`po06/lib/eval-llm.js:19` 每来一段就回调 sink，`advisor.js:253` 直接写进 `advisor-progress` 的内存记录，逐块、无攒批。
- provider 也不是：实测 326 块 / 2171ms（≈150 块/秒；块间隔中位 0ms、p90 15ms、最大 111ms）。

## 2 改法

- 客户端：轮询 800ms → **25ms**（与拦截那条同一档），并把增量拼进本地缓冲。
- 服务端：按客户端给的 `since`/`draftSince`/`draftRound` **只回新增的那一截**；偏移落不进保留窗口、或回合号不一致 ⇒ 回全量 + `resync`。
- 不做增量时的实测：25ms 轮询 85 次 / 2.6s，其中 55 次有新内容（65%），平均单次载荷 526B、最大 540B。
- 若不回增量，同样的节拍每次要传整段正文（最长 24000 字），所以增量和节拍必须一起改。

## 3 复查后修掉的失败面

| 面 | 修法 | 用例 |
|---|---|---|
| 跨回合 draft 归零 + 字数碰撞 ⇒ 新片段拼到旧正文后 | 服务端加 `draftRound` 判断，不一致直接 resync | 「跨回合偏移碰撞」（变异：关掉判断立即报红） |
| 轮询链无单次超时，一次挂起就停死 | 每次请求 8s 超时，且区分「卸载取消（停链）」与「超时取消（继续排）」 | 「轮询链有超时与空转退避」 |
| 记录不存在时按 25ms 永久空转 | `advisorNextDelayMs` 空转退避到 250ms | 「下一次排多久」 |
| 活动封顶 24 后新活动不触发重绘 | key 改认最后一条活动的 `at+tool` | 「活动封顶后仍要重绘」（变异：固定 key 立即报红） |
| 旧宿主不认识 `since` ⇒ 会退化成 25ms 全量拉取 | 以「要了增量却没拿到」为准，连续 3 次即降级：不再带参数 + 放慢到 200ms | 「旧宿主降级」（变异：去掉计数立即报红） |
