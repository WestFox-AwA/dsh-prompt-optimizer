# 架构 v4：探针优先的适应式计划（Probe-First Adaptive Plan）

日期：2026/09/16　启动：「V4 之旅」　状态：**已上线**（`STRATEGY = 'v4'`，热重载生效，无需重启）

## 一、为什么推翻 v3（清单库）

v3 想用"领域清单库"覆盖未知约束。它的致命缺陷是**逻辑上的**：
把"未知"预先转化成"已知"，必然要人工维护、随领域爆炸、换个人用就废、也无法版本化交给他人。
坦克案例暴露的四层地雷（CDN 不可用、WebGL1 下 `#extension` 位置、FBO 不完整、泛光阈值/cubemap 自反馈）
**都不是能靠枚举穷尽的**。

## 二、三条不变式（全部有实测支撑，一切写法由它们推出）

| # | 不变式 | 证据 |
| --- | --- | --- |
| ① | 员工只做明说的 → **覆盖率 ＝ 完成率** | 三轮无优化修复：它每轮只修被点出的那一个现象，绝不自查其它 |
| ② | 优化器在想象里写、员工在真实里做 → **不确定的事实一律改写成探针** | 黑屏/过曝的真正原因只能从真实媒介里发现 |
| ③ | 不能失败的检查 ＝ 装饰 | 它的桩把 `COMPILE_STATUS` / `checkFramebufferStatus` 硬编码为成功，等于把验收删掉 |

## 三、v4 的核心机制

> **凡是优化器不能确定的事实，不写进计划，改写成"探针"：一个能在真实媒介里用是／否回答的最小实验，
> 连同"失败长什么样、失败时改走哪条路"。**

领导不必亲自下车间，但必须把"看到什么就怎么做"写进指令。于是**不需要任何领域知识库**：
领域约束由探针在运行时从媒介里问出来；模型自身知识只用来"设计探针"，不用来"断言事实"。

计划固定六节（缺一节不合格）：
`一、目标与判据`（含"成功/失败长什么样"+ 主观词翻译）→ `二、观测点与基线` →
`三、步骤`（风险优先；每步：动作｜预期｜若不符怎么办）→ `四、探针清单` →
`五、隐含要求`（只加检查与约束，不加工作量）→ `六、交付物与回执`（原始证据 + pass/fail + 未验证清单）

外加：手段全开／范围冻结；代理只能定位不能判定；观测点建不起来就停下来报告；不得把该员工做的事推给用户。

## 四、首次真实产出（活实例实测）

请求（20 字）：`坦克的履带显示不出来，你帮我看看修一下。`
输出：4397 字符、六节齐全。摘录（**未经人工编辑**）：

- 失败判据自己包含了风险优先：*"页面/程序打开后连坦克车体都不出现 → 属于'跑不起来'，先解决，不算修履带。"*
- 探针 #2：*"不确定履带是独立资源还是代码生成 → 读履带节点定义；若引用外部 URL，用 Network 看状态码；404/0 字节算失败 → 按项目已有资源目录修正路径；资源确实不存在则报告，不擅自生成新素材。"*
- 探针 #3：*"不确定是'没渲染'还是'渲染了但和背景同色' → 临时把履带材质改成高饱和荧光色后截图。"*
- 探针 #4：*"不确定是否只在特定尺寸/浏览器/无头模式下丢失 → 同一页面用有头与无头各开一次，两种尺寸。"*
- 隐含要求里写死了反代理规则：*"无头模式只能作为辅助定位手段，不能单独作为'完成'的判定依据。"*
- 范围冻结：*"不碰车体几何/贴图、UI、构建配置、依赖版本……采用解读：本次不做'让履带更好看'。"*

对比：旧策略（v2.x）给的是"步骤 + 预期"，**没有探针、没有失败签名、没有基线**；黑屏与本轮过曝都属于"没被写到的失败"。

## 五、怎么证明它有效（主指标就是用户的目标函数）

**一次性通过率**：用户一句话、无人工二次指挥，交付在真实媒介里被独立判定通过。

| 指标 | 说明 |
| --- | --- |
| 一次性通过率（主） | 与旧策略同批次配对，n≥2 |
| 交付媒介验收通过率 | 判定器在真媒介里判（无头浏览器 + 像素统计），全零 LLM |
| 未验证项数 | 交付时还剩多少"没人看过"（应为 0 或如实标 fail） |
| 探针成本 | 用了多少探针/时间把不确定清除（防止"探针爆炸"） |

任务集须**跨域**（HTML/3D、CLI、数据、文档、UI），以验证"通用"而非"专治 HTML"。
