# 动态试题台 · 结论与教训（持续追加）

> 目的：用**结果侧**指标（一次交付可用率，基线＝不优化）替代形态量尺。每批数据在 `batches/<batch>/results.json`。

## 批次 b20260919（seed 20260919，4 家族 × 3 臂，n=1）

- 结果：raw / v6e / v6b 三臂**全 50%**（Δ=0）——两个家族题面有 bug，两个家族**太容易**（天花板效应）。
- 教训 1：**题面必须自校验**。执行体独立指出 `typeof r[0] === 'string'` 与 `r[0] !== 'v1'` 自相矛盾（我的判据写错）；另一族的种子文件是非法 JSON。
- 教训 2：**测不出差距的试题等于没测**——raw 已经满分时，优化只有下降空间。

## 批次 b777001（硬题家族首批，n=1）

- 结果：raw 66.7% / v6er 33.3% / v6e 33.3%（Δ=−33.4pt）。
- **但 2/3 家族仍然是我的 bug**：`import { assert } from 'node:assert'` 在 Node 里不存在（三个执行体都替我发现了）；README 判据要求逐字字符串（形式稍有不同就判错）。
- 教训 3：判据要**按语义**判（要"四个旗标都写到、不虚构旗标"，不要"必须逐字等于某串"）。
- **产品侧真 bug（考试抓到的）**：`**/README*` 在只读 glob 里命不中根目录文件（`**` 被当成"至少一层目录"）→ 命令里写着"通配未命中、路径需自行确认"。已修 + `evidence/verify-read-tools.cjs` 8/8 钉死。

## 批次 b990111（自校验后的硬题批，4 家族 × 3 臂，n=1）

| 臂 | 已判 | 通过 | 首次通过率 | 平均命令字数 | 膨胀 |
| --- | --- | --- | --- | --- | --- |
| raw | 4 | 4 | **100%** | 46 | 1× |
| v6er（带读仓库） | 4 | 3 | 75%（−25pt） | 258 | 5.61× |
| v6e（不读） | 4 | 4 | **100%**（Δ=0） | 141 | 3.07× |

- **唯一的失败已归因**：命令里明确写着"脚本里没有的删掉、脚本里有而 README 没写的补上、不要臆测补写"，而执行体自己在 README 里编了个 `--verbose` —— 是**执行体幻觉**，不是臂的问题。n=1 时一次幻觉就翻转 25 个百分点。
- 教训 4：**n≥3**（同格重复），否则读不出信号。
- 教训 5（结构性）：这 4 族**对 raw 都太容易**（100%）。要测"优化能不能帮上忙"，必须用**信息不对称**的题：要求藏在仓库约定里、格式细节只能从既有文件推断、同一条改动要同步多处——这些地方"懒句子"天然会漏，而会读仓库/会补齐的 brief 才可能赢。
- 产品侧观察：**读仓库臂目前是负收益**（膨胀 5.61×、越界 1 格，产物把"我读到了什么"写成额外要求）。修完 glob 后它至少不再写"没找到"，但**读到的信息如何进产物**仍需要按 F5（出处只在改既有代码时写）继续收敛。

## 下一轮要做

1. 新家族：`convention-in-repo`（仓库里有约定文档，懒句子不读就会漏）、`multi-place-sync`（同一改动散落 3 处，只改一处即失败）、`format-infer`（格式只能从既有文件推断）。
2. `--reps=2~3` 跑同格重复，报**区间**而不报单点。
3. 臂扩展：raw / v6e / v6er / v6ar（高级+读）/ v5e（0.4.x 行为）。
4. 只在"raw 明显低于 100%"的家族上做择优——**在 raw 满分的家族上，任何优化都只能持平或变差**，那类家族只用来做"不得伤害"的护栏。
