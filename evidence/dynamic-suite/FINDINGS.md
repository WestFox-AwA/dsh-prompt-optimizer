## 批次 b20260919（seed 20260919，4 家族 × 3 臂，n=1）

- 结果：raw / v6e / v6b 三臂**全 50%**（Δ=0）——两个家族题面有 bug，两个家族**太容易**（天花板效应）。
- 教训 1：**题面必须自校验**。执行体独立指出 `typeof r[0] === 'string'` 与 `r[0] !== 'v1'` 自相矛盾（我的判据写错）；另一族的种子文件是非法 JSON。
- 教训 2：**测不出差距的试题等于没测**——raw 已经满分时，优化只有下降空间。

## 批次 b777001（硬题家族首批，n=1）

- 结果：raw 66.7% / v6er 33.3% / v6e 33.3%（Δ=−33.4pt）。
- **但 2/3 家族仍然是我的 bug**：`import { assert } from 'node:assert'` 在 Node 里不存在（三个执行体都替我发现了）；README 判据要求逐字字符串（形式稍有不同就判错）。
- 教训 3：判据要**按语义**判（要"四个旗标都写到、不虚构旗标"，不要"必须逐字等于某串"）。
- **产品侧真 bug（考试抓到的）**：`**/README*` 在只读 glob 里命不中根目录文件（`**` 被当成"至少一层目录"）→ 命令里写着"通配未命中、路径需自行确认"。已修 + `evidence/verify-read-tools.cjs` 8/8 钉死。

- **唯一的失败已归因**：命令里明确写着"脚本里没有的删掉、脚本里有而 README 没写的补上、不要臆测补写"，而执行体自己在 README 里编了个 `--verbose` —— 是**执行体幻觉**，不是臂的问题。n=1 时一次幻觉就翻转 25 个百分点。
- 教训 4：**n≥3**（同格重复），否则读不出信号。
- 教训 5（结构性）：这 4 族**对 raw 都太容易**（100%）。要测"优化能不能帮上忙"，必须用**信息不对称**的题：要求藏在仓库约定里、格式细节只能从既有文件推断、同一条改动要同步多处——这些地方"懒句子"天然会漏，而会读仓库/会补齐的 brief 才可能赢。
- 产品侧观察：**读仓库臂目前是负收益**（膨胀 5.61×、越界 1 格，产物把"我读到了什么"写成额外要求）。修完 glob 后它至少不再写"没找到"，但**读到的信息如何进产物**仍需要按 F5（出处只在改既有代码时写）继续收敛。

## 批次 b555001 / b555002（信息不对称家族 + 上下文预算，n=1）

**先做了三次校准，每次都推翻了上一版的仪器**：

1. 带工具的 agent 执行体 → 四个臂全 100%：它会**自己**去读 `CONVENTIONS.md`、自己 grep 所有出现位置。**这不是用户的下游**（PTC 一次做完、不探索），测不出 brief 的价值。
2. 换成"一次性执行体"（只看 `task.txt`，把成品写进 `answer.json`）→ 仍然全 100%：因为我把**仓库全文**塞进了快照，brief 的信息成了冗余。
3. 加**上下文预算**（`--dump=1500`，模拟真实下游的有限上下文）+ **必给目标文件**（真实情况：要改的文件一定看得到，被挤掉的是额外上下文）+ 诱饵大文件 → **终于出现区分度**。

### 机制（看产物就能看懂，这是本轮最有价值的部分）

- **端口题（读仓库臂赢在"第二处"）**：不读臂写「先确认这处就是**实际生效的入口**」→ 执行体只改 `config.json` → README 漏改 → 失败；读仓库臂写「**`README.md:3` 另见，与 `config.json:3` 一并改**；全仓库 8000 只出现在这两处」→ 通过。**这就是读工具的直接价值。**
- **约定题（读仓库臂也输）**：第一次它**只发了 2 次 glob、一次文件内容都没读**（依据索引 `paths=[]`），根本没看见 `CONVENTIONS.md` → 产物里没有约定。
  → 产品修 1：只读查证补「**先侦察**」——列根目录并读 `README*/CONTRIBUTING*/CONVENTIONS*/根目录 *.md`（约定是客观事实，必须写进命令）。
  → 复测：brief 里出现了「动手前先读 `README.md`、`CONVENTIONS.md`…按那里写的做」，但仍**只指路、没把规则本身写出来**；一次性执行体读不到文件 → 仍然失败。
  → **产品修 2（下一轮）**：读到约定后要把**规则本身**写进命令，而不是只点名文件（"新增旗标必须同步 --help/README/tests" 这一句才是可执行的）。
- **F2 修订（已落地）**：区分两种约束——① 项目里**客观存在**的约定/事实（读到的）→ **必须写进命令**；② 自己为保险加的约束 → 一句都不许写。起因就是第一次约定题三臂全败：F2 的"零新增约束"把仓库客观约定一起压掉了。

### 仪器现状与已知局限

- 一次性执行体**读不到文件**（无工具），所以"指路型" brief 在这套仪器里拿不到分——真实 PTC 能读文件，因此这条**偏严**；下一轮要么让一次性执行体带"只读文件"权限，要么把这条局限写进判据说明。
- 每格 n=1，噪声可翻转结论（b990111 里一次执行体幻觉就翻了 25pt）→ 下一步 `--reps≥3`，报区间。
- 上下文预算（`--dump`）是本轮新增的关键变量，需要多档扫描（800 / 1500 / 3000）看 brief 价值的边界。
