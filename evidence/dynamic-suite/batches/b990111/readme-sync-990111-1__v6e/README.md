# tool

## Usage

```
node tool.mjs [--help] [--json] [--dry-run] [--quiet] [file]
```

没有子命令。位置参数只有一个：`file`，指的是要读取的文件路径；省略时默认 `input.txt`。若传了多个非 `--` 开头的参数，只有第一个会被当作 `file`，其余忽略。

`--help` 的提示文本里列出了 `--force`，但脚本中没有任何读取 `--force` 的逻辑，该选项实际不起作用（待确认：是有意保留待实现，还是提示文本写错）。

选项：

- `--help`：打印 `usage: tool.mjs --dry-run --json --quiet --force <file>` 后立即退出（exit 0），不读文件，因此文件不存在也不会报错。
- `--json`：读取文件后输出 `{"file": <file>, "lines": <行数>}`（`lines` 按 `\n` 切分计数），随即退出；会跳过默认的正文打印和 `(dry run)` 输出。
- `--quiet`：不打印文件正文（`text.trim()`）；只影响正文打印，其余输出照常。
- `--dry-run`：在正常输出之后额外打印一行 `(dry run)`；不改变读取行为、不写任何文件。

行为细节：

- `--json` 优先于其余输出：命中 `--json` 时直接退出，所以 `--json --dry-run` 不会打印 `(dry run)`。
- `--quiet --dry-run` 会打印 `(dry run)`，只是不打印正文。
- 选项顺序无关紧要（内部按集合判断是否出现）。
- 除 `--help` 外，任何一次运行都会先读取 `file`；文件不存在或不可读时抛出异常并以非 0 退出（待确认：该异常的实际退出码与报错文本未在脚本中显式指定，取决于 Node.js 的未捕获异常行为）。
