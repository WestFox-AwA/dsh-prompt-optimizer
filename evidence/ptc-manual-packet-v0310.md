## T1-config（803 字）

```
在工作目录下一次性完成下面全部动作，最后打印文件内容作为证据。

1. 在工作目录创建 config.json，写入内容（紧凑格式、无多余空白、无结尾换行也可以，但必须能逐字符比对为下面这一行）：
   {"name":"demo","retries":3}

2. 在原地把它升级为 v2 格式：保留 name、retries 两个键及其原有相对顺序不变，把新增的 "enabled":true 和 "version":2 追加到末尾，顺序为 enabled 在前、version 在前述两个旧键之后。升级后的完整内容应为：
   {"name":"demo","retries":3,"enabled":true,"version":2}

3. 把该文件的完整内容打印出来（例如 cat config.json），打印结果就是交付证据。

硬约束：
- 除 config.json 外，不得新建、修改或删除工作目录下的任何其他文件。
- 最终文件必须是合法 JSON，且仅包含上述 4 个键，不能有注释、尾随逗号、BOM 或重复键。
- 不要用会重排键顺序的处理器（如直接 json.load/dump 往返）来改写已有文件，必须保证键顺序与第 2 步一致。

验收标准（三条）：
- 工作目录下存在 config.json，其字节内容逐字符等于 {"name":"demo","retries":3,"enabled":true,"version":2}（允许末尾单个换行）。
- 用标准 JSON 解析器解析该文件成功，解析结果为 name="demo"、retries=3、enabled=true、version=2，且键顺序与上述一致。
- 交付输出中包含该文件的完整打印内容。

任何不确定的地方走最保守路径（保持原有键顺序、只追加新键、不改动其他文件），并在交付里注明你实际采用的写法。
```

## T2-stats-py（612 字）

```
在工作目录写一个 Python 脚本 stats.py，实现文本文件的行数、词数、字符数统计，并支持 --json 参数输出 JSON 格式。写完后必须实际运行一次，验证两种输出都正确。

交付物：
- stats.py（位于当前工作目录）
- 一次真实运行的结果（默认文本输出 + --json 输出各一份），连同所用命令一并贴出

验收标准（全部可机器判定）：
1. `python3 stats.py <文件>` 的退出码为 0，输出能解析出三个数：行数、词数、字符数。
2. `python3 stats.py --json <文件>` 的退出码为 0，stdout 能被 json.loads 成功解析，且包含行数、词数、字符数三个键，取值与第 1 条一致。
3. 两次数值互相一致，且与测试文件人工可核对的真实值一致。

硬约束：
- 只用 Python 标准库，不引入第三方依赖。
- 统计口径自行确定并保持一致（行数以换行符计还是最后无换行也算一行、词数以空白切分、字符数含不含换行），但两种输出必须用同一套口径。
- 命令行参数顺序需容忍 `--json` 出现在文件名前后。
- 任何不确定处走最保守路径，并在交付说明里注明所采用的口径。

不要做：
- 不要只写脚本不运行就声称验证通过。
- 不要为了让数字对上而修改测试文件或硬编码结果。
- 不要扩大范围（不加其他参数、不做包结构、不写测试框架）。
```

## T3-html-cube（1212 字）

```
在工作目录里一次性做完下面这件事，中途不要停下来汇报进度或问我确认。

任务：写一个单文件 HTML，用 CDN 引入 three.js，打开就能看到一个自动旋转的立方体；页面里暴露 `window.__selfcheck()`，返回 `{checks:[{name,pass,evidence}],pass}`。写完后你自己真的跑一次这个自检，把当次运行的原样输出贴出来。

执行步骤（在同一个程序里连贯做完）：

1. 先确认工作目录（pwd / ls），把文件写在该目录下，命名 `index.html`，除非该目录已有明确的单页入口约定。
2. 写 HTML：单文件、页面代码全部内联；three.js 通过 CDN 的 `<script>` 引入（UMD 构建或 module + importmap 都行，以能真正加载成功为准）。场景里放一个立方体，在动画循环里持续推进其旋转角度，使页面打开即可看到自动旋转。
3. 在页面里实现 `window.__selfcheck()`：返回 `{checks:[...], pass}`，每个 check 为 `{name, pass, evidence}`，evidence 填可核对的具体值（加载状态、渲染器/立方体是否创建、两次采样的旋转角度数值等）。checks 至少覆盖三项：three.js 是否加载成功、渲染器与立方体是否已创建、立方体是否随时间自动旋转（间隔 100ms 以上采两次 rotation 角度，判断是否变化）。`pass` 为所有 check 的逻辑与。
4. 用当前环境可用的无头浏览器运行时（puppeteer / playwright / headless chrome 任一）实际加载该文件，在页面上下文里调用 `window.__selfcheck()`，把执行命令和返回的 JSON 原样贴进交付。

验收标准（逐条可判定）：

1. 工作目录下存在该 HTML 文件，且文件内容中含有指向 three.js CDN 的 script 引用。
2. 无头浏览器实际加载后取回的 selfcheck 结果中 `pass === true`，且 checks 每一项都同时具备 name、pass、evidence 三个字段，无缺项。
3. 交付里贴出的自检输出来自当次真实运行，执行命令与输出逐字对应，未经过改写。

不要做：

- 不要拆成多轮、不要分段交付、不要中途征求确认。
- 不要把 three.js 下载或内联到本地来替代 CDN 引入。
- 不要为了让 pass 为 true 而伪造 evidence、隐藏或删除未通过的 check；哪项没过就如实呈现。
- 不要添加与上述无关的功能、依赖、构建配置或目录结构。

任何不确定的地方走最保守路径，并在交付里注明你的选择和依据（包括运行环境本身不可用时的替代做法）。
```
