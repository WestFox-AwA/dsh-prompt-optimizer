## 任务 1 · config.json 升级为 v2

### A 组原文
```
在工作目录下创建一个 config.json，内容为 {"name":"demo","retries":3}；然后把它升级成 v2 格式：加上 "enabled":true 与 "version":2，其余字段与键顺序保持不变；最后打印文件内容作为证据。
```

```

2. 把它升级为 v2 格式：在保留原有字段、字段值和键顺序的前提下，加上 "enabled":true 与 "version":2。
3. 打印该文件内容作为证据。

验收标准（全部可观测，缺一不算完成）
- pwd 输出的路径与最终创建 config.json 的路径一致，并已报告该路径。
- config.json 能作为合法 JSON 解析成功。
- 键集合恰为 name、retries、enabled、version 四个，无多余键、无缺失键。
- 值为 "demo"（字符串）、3（数字）、true（布尔）、2（数字），类型不被改成字符串。
- name 与 retries 的相对顺序与升级前完全一致，新键默认追加在已有键之后；最终内容形如 {"name":"demo","retries":3,"enabled":true,"version":2}。
- 交付时把 cat config.json 的完整输出贴出来作为证据，并附一条 JSON 解析成功与键顺序的校验输出。

阶段 3 升级 v2：先读取当前文件，再在其基础上加入 enabled 与 version 两个键，不修改其它键名、键值、键顺序。写入后重新解析校验，特别确认键顺序未被重排。
阶段 4 证据：输出 cat config.json 的完整内容、JSON 解析结果、键顺序列表、以及最终 pwd；若曾创建临时文件，确认已删除。

硬约束
- 只用本地文件操作，不联网、不安装依赖、不修改工作目录以外的任何文件。

- 不擅自扩大范围：不新增字段、不改 name 与 retries 的值、不给文件加额外格式（缩进与否保持一次决定并一致）、不顺手重命名或移动文件。
```

## 任务 2 · 写 stats.py（含 --json，真跑验证）

### A 组原文
```
在工作目录写一个小 Python 脚本 stats.py，能读一个文本文件并统计行数、词数、字符数；再加一个 --json 参数让输出变成 JSON；加完后你真跑一次验证两种输出都正确，并把运行结果贴出来。
```

### B 组命令（0.1.1 策略产出，1571 字）
```
先建立一份 todo 列表跟踪这次任务，阶段至少包含：① 查证环境与现状 → ② 实现基础版 stats.py → ③ 加 --json 开关 → ④ 真实跑通两种输出并贴出证据。每完成一项就更新状态，不要跳步。

开工前先做查证，不要凭假设动手：
- 确认当前工作目录的绝对路径，stats.py 就写在这里。
- 确认目录下是否已存在 stats.py 或同名文件。
- 确认可用的 Python 解释器及版本（如 python3 --version）。

第 1 阶段：实现基础版
在工作目录创建 stats.py，满足：
- 接受一个位置参数：待读取的文本文件路径。
- 默认输出人类可读的三行统计：行数、词数、字符数，每行标明是哪一项，数字清晰可辨。
- 行数 = 换行符数量对应的行数；词数 = 按空白字符切分得到的非空 token 数；字符数 = 读取到的全部字符数（含空白与换行）。这三条定义按上述写死，不要自行另作解释。
- 文件按 UTF-8 读取；文件不存在或不可读时，向 stderr 打印明确的错误信息并以非零状态码退出。
- 只用 Python 标准库，不引入任何第三方依赖。

第 2 阶段：加 --json
- 增加 --json 参数，开启后输出一个 JSON 对象，字段名分别为 lines、words、chars，数值与默认输出完全一致。
- 不加 --json 时行为保持不变。
- 同时提供 -h/--help。

第 3 阶段：真实验证（必须实际执行，不许推演）
1. 准备一个测试文本文件用于验证；优先用纯 ASCII 内容并包含多行与空行，避免编码差异干扰计数。
2. 实跑默认输出：python3 stats.py <测试文件>，贴出完整命令与原始输出。
3. 实跑 JSON 输出：python3 stats.py <测试文件> --json，贴出完整命令与原始输出。
4. 用 python3 -m json.tool 或等价方式确认 JSON 可被解析。
5. 与 wc -l / wc -w / wc -c 对纯 ASCII 测试文件的结果做交叉比对，贴出两边数字；若不一致，说明差异来自何处。
6. 贴出脚本最终内容的完整代码。

验收标准（全部可观测）：
- stats.py 存在于工作目录，且能在无第三方依赖的环境下运行。
- 默认输出与 --json 输出都真实跑通，命令与原始输出已贴出。
- 两种输出的三个数字一致，且与 wc 的比对结果有明确交代。
- 文件缺失场景已实测：给出错误信息与非零退出码，并贴出该次运行的命令与输出。
- 贴出的所有输出都是终端里真实产生的，没有一处是手写或编造的。

不要做：
- 不要伪造、补写、美化任何运行输出；没跑过就不要说验证通过。
- 不要引入第三方依赖或改动工作目录里与本任务无关的文件。
- 不要用 try/except 把读取错误静默吞掉。
- 不要为了迁就数字而修改测试文件内容或篡改统计定义。
- 不要扩大范围（不加额外参数、不做打包、不写额外模块），除非我另行要求。

预案：
- 如果发现工作目录里已存在 stats.py：先读它并对照上面的要求，若存在冲突或会覆盖既有内容，先停下把现状告诉我再决定，不要直接覆盖。
- 如果 python3 不可用或版本过低：先报告实际可用的解释器与版本，不要自行安装或升级任何东西。
- 如果实测数字与 wc 不一致：先判定是行尾/空行/多字节字符等定义差异还是脚本 bug，把原因说清楚并给出结论，不要去改测试数据凑结果。
- 如果读文件触发编码错误：报出明确的错误信息并让我知道，不要静默忽略、跳过或替换字符。
- 如果工作目录不明确：先确认清楚再落盘，不要写到别的位置。
```

### A 组原文
```

```

### B 组命令（0.1.1 策略产出，2109 字）
```
先建立 goal：交付一个单文件 HTML，满足"打开即见自动旋转立方体"+"文件内暴露 window.__selfcheck() 自检并真实跑通"，并建立 todo，按下面阶段推进，每阶段完成并给出证据后才进入下一阶段。

**阶段 3：真实执行自检**
1. 用阶段 1 确认过的工具，对 cube.html 真跑一次：加载页面、调用 window.__selfcheck()、把返回的 JSON 原样打到终端。

1. 工作目录下存在 cube.html，单文件，除 CDN 外不依赖任何本地其它文件。
2. 文件内可搜到 three.js 的 CDN script 标签，且版本号固定。
3. window.__selfcheck() 存在，返回值结构严格符合 {checks:[{name,pass,evidence}],pass}，checks 非空。
4. 贴出的运行输出中 pass === true，且每项 evidence 都是非空的实际证据文本，不是占位说明。
5. 输出中能看到立方体旋转随时间变化的实测数据。

**硬约束**
1. 只新增这一个文件，不改动工作目录里其它任何文件。
2. 自检结果必须是真跑出来的，不许手写、不许预估、不许用"应该能通过"代替。
```
