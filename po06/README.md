## 30 秒：装到独立 profile、启用、关掉

**① 装进一个独立 profile**（**别装进你每天在用的那个**——旧插件与新插件同装配会被拒绝启用）：

```powershell
# 用发行版自带的 web 模板新建一个干净 profile（不含 0.5.x）
dsh --profile po06beta --from-default-profile web --dump-config
# 装本包（tgz 路径换成你下载到的位置）
dsh plugin --profile po06beta add <path>\dsh-external-dsh-po06-0.6.0-beta.4.tgz
# 一条命令确认"装好了、装的是这一份、会被装配、启用会生效"
node <repo>\po06\scripts\check-install.mjs --profile po06beta --expect-version 0.6.0-beta.4
```

`check-install.mjs` 会逐条回答（**不调模型、不花钱**）：

- **装上了吗**：profile 的 `dependencies` 里有没有这个包；
- **装的是这一份吗**：把装出来的 `lib/*.js` 与仓库**逐文件比 sha256**
  ——这个项目在"装的是新件还是 pnpm 缓存里的旧件"上**栽过两次**（EV-0079/0083），
  而那种失败**不报错**，只是行为像没装；
- **会被装配吗**：`--dump-config` 的组合树里有没有这一层
  ——**装了但不在 `dsh.profile.bundles` 里 = 永远不会生效**（EV-0066）；
- **启用会生效吗**：用**装出来的那份**解析器读配置（不是我复述规则），并说明旧路径为什么不会被误认。

**② 启用**（写 0.6 **自己的**配置文件；**不会**碰 0.5.x 的 `prompt-optimizer.json`，见 EV-0111）：

```powershell
Set-Content -Path "$env:USERPROFILE\.dsh\po06.json" -Encoding utf8 -Value '{"settingsVersion":1,"enabled":true,"rollout":{"mode":"all"}}'
```

**③ 用那个 profile 开工**：`dsh --profile po06beta`（它会启动该 profile 的应用并打印带 token 的地址）。
⚠ **`--profile` 必须写在子命令之前**：`dsh --profile po06beta …` 可以，`dsh web --profile po06beta` **不行**
（`web` 子命令明确拒绝父级的 `--profile`，实测报 `web takes none of parent --profile`）。
默认端口被占用时加 `--port 3081`。
**效果从第 2 步起可见**：意图包是"零延迟"的——它总是比当前这一步晚一拍
（同一轮里第 2 步就能看到，跨轮则是上一轮的包）。**这是设计，不是 bug。**

**④ 关掉 / 卸掉（随时、一步）**：

```powershell
# 关：把 enabled 改 false（或直接删掉这个文件——读不到就是不启用）
Set-Content -Path "$env:USERPROFILE\.dsh\po06.json" -Encoding utf8 -Value '{"settingsVersion":1,"enabled":false,"rollout":{"mode":"off"}}'
# 卸：从 profile 移除并把 profile 整个删掉
dsh plugin --profile po06beta remove @dsh-external/dsh-po06
Remove-Item -Recurse -Force "$env:USERPROFILE\.dsh\profiles\po06beta"
```

> **为什么单独一个 profile**：你每天用的 `web` profile 里装着 **0.5.x**，而且
> `<home>\prompt-optimizer.json` 是它**正在使用的设置**（tier/strategy/ui…）。
> 0.6 早先把启用意图写在同一个路径上——那意味着"想试试 0.6"要先破坏你每天在用的插件。
> 已改掉：0.6 读自己的 `po06.json`，旧路径只做**只读回退**且必须带 0.6 标记（EV-0111）。

## 跑完之后：怎么看它到底做了什么（`recap.mjs`）

真实项目里用过一轮之后，留下的东西只有三样，**都在 `<home>` 下**：

| 文件 | 是什么 |
|---|---|
| `po06-wire.jsonl` | **每轮用户输入的判定台账**：成没成、包多大、第几版、走了哪些环节 |
| `po06-state/<sessionId>.json` | 该会话的**意图条目**（每条带出处：你说过 / 机器补充） |
| `po06-reports/*.json` | 自检报告（只在显式自检时写） |

一条命令把它整理成人能读的一页（**不调模型、不花钱**）：

```powershell
node <repo>\po06\scripts\recap.mjs --home "$env:USERPROFILE\.dsh"
# 只看某个会话： --session <id前缀>       机器读： --json out.json
```

它回答两个最该被问的问题：

1. **"它有没有参与？"**——逐轮列出 `committed / skipped / …` 与**意图包字符数**；
   没提交的轮次**单独列出来并给出理由**（而不是安静地什么都不做，EV-0078 的教训）。
   台账为空时它会直接告诉你"**一次都没被触发过**"（多半是没启用，或装到了别的 home）。
2. **"它替我说了什么？"**——把条目分成 **"你说过"** 与 **"机器补充"** 两类，
   并统计**无出处条目数**：按契约那个数**必须是 0**，不是 0 就以**非零退出码**报出来
   （无出处 = 不知道是谁说的，那是缺陷，不是排版问题）。
3. **"跨会话有没有串味？"**——每条条目的出处必须落在**它自己所在的会话或它的祖先会话**里。
   **分叉继承来的条目指向父会话是「正确」的**（"这句话是你在父会话里说的"），
   所以判据不能写成"出处必须等于自己"——那会把合法继承全判成泄漏。
   指向**链之外**的会话 = 把别处的话当成你在这里说的 ⇒ **非零退出码**。

> 读法的关键：**"你说过"的条目必须是你真说过的原话**——0.6 的契约要求逐字引文，
> 对不上整份输出作废；而"机器补充"是它自己的判断，**不得被当成你的命令**。
> 这一页**只做事实整理，不做质量判定**：哪一版答案更好只能你自己读。

### 顺带能把「分叉继承」验掉（A7 的另一半）

在 GUI 里对一个**已经用过**的会话点**分叉**，在子会话里**说一句话**，然后重跑上面的命令：
「**〇、分叉继承**」那一节应当出现一行，写明子会话、继承自哪个父会话、继承到的版本。

- **有那一行** ⇒ 宿主分叉时 0.6 **确实**把父会话的意图状态派生给了子会话
  （深拷贝 + 改写归属 + 留下出处，ADR-0039）。
- **没有那一行而你确实分叉过** ⇒ 继承**没发生**：子会话会**从零开始**，而且**不会有任何提示**
  ——这正是那条 ADR 要防的"静默无状态"。

## 花钱之前：预检（`preflight-e001.mjs`）

留出评估的每一次运行都要花钱，所以**先花零成本问清楚"这一期到底能测到什么"**：

```powershell
node <repo>\po06\scripts\preflight-e001.mjs --stage S4 [--budget <n>]
```

它逐条报出（**不调模型、不花钱**）：

| 检查 | 为什么 |
|---|---|
| 封存 hash + 题数，**外加一次负向自检** | 只报"校验通过"没有意义——要证明**篡改真的会被拒** |
| 每题的**判据适用性** | S1 的教训：那一期 6 题里 **0 题**适用「约束守住」，而这件事是花掉 103k **之后**才发现的 |
| 上界 / 期望 / **其中解释层的前置花费** | 跑之前要花的钱与跑起来要花的钱是两笔 |
| 预算判定（低于上界直接拒绝） | 避免跑到一半没钱 |
| 包缓存：哪些题**不再花解释层的钱** | 缓存存在但一个都不匹配本期题号时会**明确警告**（别把"有缓存"读成"不花钱"） |

## 它想做什么

让用户在**少写提示词**的情况下更准确地传达意思，并让工作 AI 做得更好、更稳，同时不违背用户本意。

做法上的三个关键选择：

1. **原话保留，机器补充另附** —— 用户的话永远原样留在人类消息里；
   机器的解释以**带来源标签的分节**形式附在上下文里（`systemPrompt.context` → 宿主的 `form:'snapshot'` 聚合消息）。
   质量展开有地方放（「质量解释…不是新增命令」节），但不可能被读成用户的命令。
2. **`user_requirement` 必须带逐字引文** —— 引文必须是用户原话的**字面子串**，对不上则整份输出作废。
   这把「机器替用户发明要求」从信任问题变成**字符串比对问题**。
3. **检测到问题不等于可以动手** —— 只有 `fail` 能触发返工；
   基础设施故障与未知都不算；返工默认**只记录不发送**（三级投递 L0）。

## 已知限制与风险

- **`unknownClass` 路由当前"机制就绪、输入缺失"**：真实模型不输出该字段（两次实测），
  所有未知退化为「用户偏好」，靠批次上限（默认 2）兜住问卷风险。
  代码里用 `unclassified` 计数把它**显示出来**，不静默降级。
- **`informational` 检查没有被守卫**：若有人把决定性检查误标为 `informational`，会造成漏判。
- **交付门生产触发默认关闭**：每次交付都启动浏览器是重操作，是否开启属设置决策。
- **旧插件探测的静态分支会误报**（装了但禁用），这是刻意的保守方向。
- **状态只保留最近 200 个会话**（`po06-state/` 按文件修改时间淘汰，`DEFAULT_KEEP = 200`）。
  超出之后**更早会话的意图状态会被删掉**——那个会话本身照常能打开、能继续用，
  只是 0.6 不再记得它的约束（**不会有提示**）。保留份数目前写死，改它要动代码。
- **状态文件读不出来时**（JSON 坏 / 形状不对）0.6 会把坏文件**改名留证据**
  （`<会话>.corrupt-<时间戳>.json`）、记一条 `state-unreadable` 台账，然后按"尚无状态"继续。
  **它不会静默覆盖那份文件**；这类事件会在 `recap.mjs` 里单独列出（并让退出码非零）。
  若你在那里看到这一节：**残骸文件里很可能就是丢失的长期约束**。

## 回滚方式

**最短的一条**（beta 期间推荐）：把 `po06.json` 的 `enabled` 改成 `false`，或**直接删掉这个文件**
——读不到即不启用，且**不影响你原有的 0.5.x**（两者不是同一个文件，EV-0111）。

1. 若已注入：`dev_uninject_plugin`（或从 profile 移除 junction 与 patch 条目）。
2. 若已迁移配置：从 `<home>/backups/prompt-optimizer.<时间戳>.bak.json` 还原
   （`rollbackConfig`，**回滚不会删除备份**）。
3. 旧版本插件不受本包影响；`@dsh-external/dsh-prompt-optimizer`（0.5.x）仍在原处，
   它的设置文件 `prompt-optimizer.json` **全程只被 0.6 只读回退读取**，从未被写。
