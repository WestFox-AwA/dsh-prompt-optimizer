## 一、S1 要回答的问题

0.6 的核心主张是：**在用户说得少的情况下，把意图补成下游一次做对的命令，且不越界、不缩水、该问才问。**
S1 用留出集（`HOLDOUT-v1.md`，已封存 sha256 `71b8956d…`）里**判据为二值、不需要审美**的 6 道题，
对照两臂：

| 臂 | 内容 |
|---|---|
| **A** | 用户原话直发 |
| **C** | 用户原话 ＋ 0.6 编译的意图包 |

两臂系统提示词**相同**（23 字符）；温度 0.3；**都没有工具**（`buildArmMessages` 只发纯文本，
`complete()` 不传 `tools`）——这一点后来变得很关键。

## 二、设计与花费

- 6 题 × 2 臂 × 3 轮 = **36 个单元**；单模型（`deepseek-v4.1-flash-expires-on-0910`）、单次运行。

## 三、结果（按可信度分层）

### ✅ 可信

| 维度 | 结果 |
|---|---|
| 单元产出 | **36/36，0 失败** |
| 放大约束（答案是否新增用户没说过的硬约束） | **A 0 / C 0** ⇒ **不判别**（至少 C 没把包内容变成新硬约束） |
| 答案长度 | A 14,521 / C 13,249 字符 ⇒ **相当**（C 不是"话更多"） |

| **稳定性**（同题同臂 3 次采样的词集相似度 / 长度 CV） | **A 0.119 / 0.222 · C 0.074 / 0.374** ⇒ ⚠ **C 更不稳定**（第一条两臂有差别的判据，且不利于 C；见 EV-0099） |

### ❌ 已撤回（曾被我当作结论）

| 曾声称 | 为什么撤回 |
|---|---|
| "C 臂问得更多、且更多是**不该问的实现细节**"（A5/C12 → 有效集 A4/C9） | 该指标是**单词命中**分类：`implementation` 优先，且标记词里有 **`package`**（H-07 的**题面名词**）。**只删这一个词**，C 臂坏分降 **25%**（12→9）而 A 臂完全不变（5/8）⇒ 指标在**制造效应**：越贴题越吃亏（EV-0094） |
| H-11 是"最尖锐"的证据（C 1→3） | H-11 判据要求"**自己去读仓库**"，而两臂**都没有工具** ⇒ 该判据**两臂都无法满足**，问用户反而是唯一诚实动作（EV-0093） |
| 【未决项】段导致 C 臂多问 | 已实验否证：去掉该段后问句总数降（19→15）但"不该问"类**一条没少（6→6）**；且 H-07 的包只有 280 字节、**根本没有未决项段**（EV-0090） |

## 四、这一期发现的三个**我自己的**仪表缺陷

1. **答案正文没落盘**（run1 白花 42,884）：`runUnits` 的 record 只存 `chars`。
   → 已修：record 存 `text`/`reasoning`，并按单元落 `units/<unitId>.md`。
   **教训：跑之前先问"判据需要的东西存下来了吗"**。
2. **包正文没落盘**：想验证假设时手上没有包，只能再付一次解释层的钱。
   → 已修：包落 `packets/<taskId>.md` 且**可复用**（重跑不再付解释层）。
3. **判据本身把任务名词当特征**：见上表。→ 已修词表＋写明"不得当判据"。

> 三者同源：**仪器必须先被检验**（ADR-0034）。我在"单元能跑通"上做了验证，
> 却没在"判据可不可靠""题目可不可满足""证据会不会留下"上做验证——顺序反了。

## 五、S1 因此**不**能说明什么（防止被引用过头）

- ❌ 不能说"0.6 有效"——没有任何判据显示 A 与 C 有差别。
- ❌ 不能说"0.6 无效"——"该不该问"和"约束守住"**根本没测到**，而这两条恰是 0.6 的立身之本。
- ❌ 不能外推到 S2/S3（视觉质量、长任务、并发）——**一期都没跑**。
- ❌ 不能外推到真实宿主行为——本实验是**无工具单次补全**，不是真实会话
  （真实会话的投递链路另在 EV-0080/0081/0085 验证过）。
- ⚠ n=3/题、单模型、单次运行。
